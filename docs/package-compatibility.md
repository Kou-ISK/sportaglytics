# パッケージ互換・原本保護・Sportscode XML取り込み

## 対応範囲

拡張子だけで互換性を決めません。読み込み前に設定・Timeline・映像参照を検証します。`.stpkg`はディレクトリ型です。

| 入力                                                              | 判定と結果                                                                                                                       |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 現行 `.stpkg`                                                     | 設定の`packageFormatVersion`未指定または1、`timeline.json`のversion 2、既知のアングル/クリップ構造を確認して開く                 |
| 旧 SporTag `.stpkg` / 拡張子なしのフォルダ                        | 旧Timeline配列、`tightViewPath` / `wideViewPath`、または映像参照のみの旧アングルを識別し、原本を保持して別の`.stpkg`へ移行コピー |
| 不明な設定version・Timeline version・不正時刻・重複ID・壊れたJSON | 推測で補修せず拒否。原本を保持                                                                                                   |
| 存在しない映像・範囲外の相対参照・symlink                         | 読み込みまたはコピーを拒否。外部の絶対参照は完全なパスを維持し、同名ファイルへ置き換えない                                       |
| Sportscode XML + 明示的に選択したローカル映像                     | 下記の専用操作で別の新規`.stpkg`を作成                                                                                           |
| Sportscode `.scpkg` / `.sczip`                                    | ネイティブ形式は未対応。拡張子変更や内部ファイルの推測では開かない。SportscodeからXMLを出力して使用する                          |

JSONは1ファイル16 MiBまでです。旧構造の`actionType` / `actionResult`はType/Resultラベルへ移します。現行Timelineは行順・行色・空行と場面を持つversion 2です。すべての歴代SporTag版・外部アプリ版の互換を保証するものではありません。

## 旧フォルダを安全に開く

1. 起動画面の「旧SporTagフォルダを開く」から原本を選ぶ。`.stpkg`は「パッケージを開く」から選ぶ。
2. 内容と映像の存在を確認する。通常は隣に移行先を作る。旧`.stpkg`は`-migrated.stpkg`、拡張子なしは`.stpkg`を付ける。
3. 書き込み権限がない場合は、保存先を指定する。取消ではコピーを完成させず、原本は保持する。
4. コピーだけの設定・参照・Timelineを現行構造へ変換し、再検証後に同じ保存先内のrenameで完成させる。以後の編集は新しいコピーへ保存する。

同名の無関係な保存先は上書きせず、通常の隣接コピーには連番を付けます。原本のreal pathとfingerprintが同じなら、再検証した既存コピーを再利用します。fingerprintは全エントリーの位置・サイズ・mtime・modeと小さな設定文書の内容を含みます。大きな映像の全バイトはhashせず、同サイズ・同mtimeの映像変更を完全には検出できません。

空き容量はコピー対象の総サイズ + 16 MiBを事前確認します。必要容量は外部参照の映像を含むコピー量やファイルシステムの実割当量を完全に表すものではなく、途中の容量変化も起こり得ます。権限・容量不足・コピー/rename失敗では一時コピーを除去し、原本を保持します。処理中にアプリを強制終了すると一時フォルダが残る可能性があります。完成したプロジェクトとして扱わず、自動削除もしません。ネットワーク共有のrename特性、電源断後の耐久性、別プロセスによる同名保存先の競合は別途確認が必要です。

内部の絶対映像参照はコピー内の相対参照へ変換し、外部の絶対参照はそのまま保ちます。異なるファイルをbasenameで探し当てる復旧はしません。外付けドライブが必要なら接続してから再試行してください。

## 読み込み・保存の失敗

Timelineの読み込みが成功して検証が完了するまで自動保存と文書変更を抑止します。読み込み失敗を空のTimelineとして保存しません。映像画面と独立Timelineにエラーを残し、「再読み込み」で原本からやり直せます。

保存失敗では画面上の変更を保持し、「保存を再試行」を表示します。権限、保存先、空き容量を直してから再試行してください。保存はファイル単位で順番を守り、同じディレクトリの一時ファイルへ書き込み・sync・close後にrenameします。既存ファイルの書き込み権限を確認し、modeを維持します。一般のテキスト保存IPCもこの処理を使います。

未保存の変更があるまま終了した場合の終了確認や、最後の300 ms debounceを必ずflushする処理はありません。保存失敗の表示が消える前に終了しないでください。原本保持と原子的なファイル置換は、停電時の耐久性・所有者/xattrの保持・全形式の保存成功を意味しません。

## Sportscode XMLから新規作成

1. Sportscode側でEdit List XMLを出力する。起動画面の「Sportscode XMLから作成」を開き、`.xml`を選ぶ。
2. 対応するローカル映像を明示的に1本選ぶ。`.mov` / `.mp4` / `.m4v` / `.webm`を受け付ける。
3. プロジェクト名、行/場面数、時刻範囲、警告を確認する。必要な秒数補正を入力する。開始と終了へ同じ秒数を加算する。
4. 映像と時刻・警告を確認したチェックを付け、保存先フォルダを選ぶ。取消では新規プロジェクトを作らない。
5. 映像をコピーして実尺を調べ、場面が映像の範囲に収まることを確認した後に新規`.stpkg`を完成させて開く。既存分析は置き換えない。

[Sportscode v10公式マニュアルのXML仕様](https://static.hudl.com/craft/SportsCodeManual-2.pdf)の`file / ALL_INSTANCES / ROWS`を基にした厳密なsubsetです。instanceの整数ID、秒単位の小数start/end、code、labelのtext/group、free_text、行名・順番・16bit RGB色を取り込みます。空行、同じ文字列でgroupが違うラベル、改行・日本語・emojiを保持します。欠けている行はcodeから導出します。XMLのescaped characterはdecodeします。

`SESSION_INFO/start_time`は表示用メタデータです。録画日時から秒補正を推測せず、前後半や動画の結合位置も推測しません。補正後の負時刻、終了<開始、24時間超、映像尺超過は拒否し、切り詰めません。DTD/ENTITY、namespace、属性による未対応version、不正XML、重複IDや行名、不明な重要構造は拒否します。未対応の補助フィールドやsort指定は警告して、反映する値を確認します。旧Sportscodeが出す非標準・壊れたXMLを勝手に修復しません。

XMLのSHA-256、選択した映像名、秒数補正、警告を新しいコピーのメタデータへ記録します。完了直前にXML hashと映像のサイズ・mtime・inodeを再確認します。元XML・元映像・ネイティブSportscodeパッケージを変更せず、クラウドへ送りません。ネイティブパッケージ内部は新規保存先にできません。これはXMLの新規プロジェクト取り込みであり、Sportscodeの全機能やネイティブ形式の往復互換、XML出力、既存プロジェクトへのmergeではありません。

## ファイル選択と検証の限界

macOSの`.stpkg`選択はopenFile/openDirectoryとstpkg filterを設定します。Windowsはディレクトリ型のためopenDirectoryを使います。Windowsのフォルダ選択には拡張子filterが効かないため、メッセージと構造検証で案内・制限します。旧フォルダ、XML、映像、保存先は目的別のダイアログです。取消や保存先フォルダを最近開いたプロジェクトへ登録しません。

合成データのunit/Electron回帰は[Testing](testing.md#パッケージ互換と保存保護)を参照してください。実Finder/Explorerの見た目、外付け実機、ACL、全歴代形式、Sportscode実機でのXML出力は自動テストだけでは確認できません。ローカルの実候補調査はメタデータと参照の存在確認のみとし、実データの移行・映像読込・外部uploadの証拠にはしません。
