# 起動画面とパッケージを開く操作

起動画面は、既存の分析を再開するか、新しい映像からパッケージを作成する入口です。初回案内を完了した後も製品名・操作・履歴を表示します。

## 操作

| 目的                 | 操作                                                       | 結果                                         |
| -------------------- | ---------------------------------------------------------- | -------------------------------------------- |
| 既存の分析を再開     | 最近開いたパッケージの行をクリック、またはTabで選んでEnter | その保存先から読み込む                       |
| 履歴から探す         | 「履歴を検索」に名前・チーム・保存場所の一部を入力         | 大文字小文字を区別せず、履歴内を絞り込む     |
| 別のパッケージを開く | 「パッケージを開く」またはファイルメニュー                 | OSの選択ダイアログを開く                     |
| ドロップで開く       | `.stpkg` を1つ起動画面へドロップ                           | preloadで実ファイルのパスを取得して読み込む  |
| 初めて使う映像を追加 | 「新しいパッケージを作成」                                 | 名前・チーム・映像を指定するウィザードを開く |
| 履歴から除く         | 行末の×                                                    | 履歴だけを削除。パッケージ本体は残る         |

映像ファイルを直接起動画面へ落としても、既存パッケージとしては開きません。新規作成ウィザードから映像を追加してください。複数パッケージを同時にドロップする操作にも対応しません。

履歴は最終利用順で最大6件をこの端末に保持し、ファイルメニューと同期します。履歴の行には名称、チーム、保存場所、映像数、最終利用日を表示します。長い文字列は一行省略し、名称・場所の完全な値はツールチップで確認できます。検索はファイルシステム全体を走査しません。移動済みファイルや未接続ドライブも、開く前には利用可能か判定しません。

履歴の登録は起動画面のReact state更新と分離し、メタデータ取得が画面切替後に完了しても保存します。登録・削除では端末の最新の履歴を読み直し、別のウィンドウが追加した履歴を保持します。

## 読み込みと復旧

開く操作・最近の履歴・ドロップ・OSからの要求は同じロード処理を使います。選択ダイアログから読み込みが完了するまで新たな開く操作を抑止し、起動画面の操作を無効にして進行状況を表示します。ダイアログの取消ではエラーを表示しません。

失敗時は画面内にエラーを残し、保存先やドライブの確認を案内します。「もう一度開く」で同じパスを再試行でき、「パッケージを開く」で移動先を選び直せます。「詳細を表示」にはパスとエラー情報を表示し、コピーできます。履歴や元ファイルを自動で削除しません。

映像ウィンドウを閉じると、そのパッケージのSessionと所有する補助ウィンドウを終了します。同じパッケージは再びドロップ・履歴・ファイル選択・OSからの要求で開けます。macOSではウィンドウをすべて閉じてもアプリは終了せず、Dockから起動画面へ戻れます。

ファイル形式や個数が違うドロップでは、読み込み失敗とは区別して「ドロップしたファイルを確認してください」と表示します。「パッケージを選んで開く」で選び直せます。この段階では保存先へのアクセスに失敗していないため、ドライブの接続確認は案内しません。履歴の文字列など、ファイルを含まないドラッグは無視します。

`.stpkg` はディレクトリ型のパッケージです。旧形式は既存のロード時移行を通します。Package Sessionの所有権とウィンドウ復元の契約は[ADR 0026](adr/0026-package-session-window-ownership.md)を参照してください。

## 実装の責務

| 責務                                                      | 正本                                                                                                     |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 起動画面の構成とcallback                                  | `src/features/videoPlayer/components/Setup/VideoPathSelector.tsx`                                        |
| 外部依存のない画面・状態表示                              | `../VideoPathSelectorView.tsx`、`components/RecentPackagesSection.tsx`、`components/StartStatusView.tsx` |
| 検索入力・作成ウィザード・読み込み後の反映                | `hooks/useVideoPathSelectorController.ts`                                                                |
| ダイアログ・履歴・drop・native menuのロード状態と購読解除 | `hooks/useStartPackageOpen.ts`                                                                           |
| ドロップの単一ファイル検証                                | `hooks/useDragAndDrop.ts`                                                                                |
| パッケージ読込・型検証・Session・移行                     | `gateway/packageGateway.ts`                                                                              |
| 履歴の保存・上限・メニュー同期                            | `gateway/recentPackagesGateway.ts`                                                                       |
| Fileから実パスを得る境界                                  | `src/renderer.d.ts` の `resolveDroppedPackagePath`、`electron/src/preload.ts`                            |

表中の相対パスは `src/features/videoPlayer/components/Setup/VideoPathSelector/` を基準とします。ViewはIPC・永続化へ依存せず、検索やロード状態をpropsとして受け取ります。native menuのイベント購読を複数のロードhookへ分散させません。

## 検証

Storybook `Workspace/Start` で初回・履歴あり・検索なし・読み込み中・エラー・有効/無効ドロップ・長い名前を確認します。dark/light、600/800/1280pxで操作ラベルの折り返しや横方向のはみ出しを確認します。

実機では、OSの選択ダイアログ、Finder/Explorerからの`.stpkg`ドロップ、存在しない履歴、外付けドライブの再接続、旧形式移行、複数ウィンドウのSession復元を確認します。Storybookの成功だけをElectronのファイル操作が成功した証拠にしません。

`pnpm run test:e2e:package-reopen` は日本語・空白・`#`・`%`を含む実パッケージをChromiumのファイルドロップ経由で開き、映像ウィンドウを閉じて同じパッケージを再度開きます。補助ウィンドウの終了も確認します。macOSではDock相当の再表示後にdrop・履歴・選択ダイアログ経由で繰り返し開きます。ダイアログの選択結果だけをテスト内で指定し、ファイルの判定とロードは本番経路を使用します。
