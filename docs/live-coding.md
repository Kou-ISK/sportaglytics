# ライブキャプチャとコーディング

カメラを録画しながら、通常の映像ウィンドウ・タイムライン・コードウィンドウでコーディングできます。保存先はローカルの `.stpkg` です。サーバー契約やクラウドへの映像送信は不要です。

## 入力方式

| 入力                  | 接続条件                                                                                                                 | 音声                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------ |
| USBカメラ・HDMIカメラ | OSからカメラとして見えるUSB/UVC入力。HDMIカメラにはUSBキャプチャ機器が必要。PCのHDMI出力端子へ直接つないでも取り込めない | 「音声入力」で対応するキャプチャ音声を選択 |
| iPhone / Mac          | Appleの連係カメラが利用可能で、OSのカメラ一覧に現れること。有線・無線の条件はAppleの案内を参照                           | OSで認識されたマイクを選択                 |
| iPhone / Windows      | OSにカメラを公開する対応ドライバ・アプリ、または下記のIP配信方式に対応するカメラアプリが必要                             | 選んだ入力による                           |
| IPカメラ・エンコーダ  | RTSP(S)、RTMP(S)、HTTP(S)の直接映像URL、HLSプレイリスト。アプリから接続するpull方式                                      | 配信に含まれる最初の音声トラック           |

アプリ全体で同時に1つのライブ録画、1録画につき最大4入力、最大24時間です。保存済みの区間は1アングル最大50,000区間で、通常のインポート画面の映像ファイル数上限とは区別します。USB入力とIP入力を混在できます。同じUSBカメラを複数入力へ重複指定しないでください。最大1080pまたは720p、30fpsでH.264/AACへ保存します。元の解像度以上には拡大しません。無圧縮・ビット単位の原画保存ではありません。

SRT、NDI、ONVIFによる自動探索、RTMP受信サーバー、専用iPhoneアプリは実装していません。ブラウザで見るカメラの管理画面URLやYouTube視聴URLは直接映像URLではありません。機器の対応方式・ドライバ・OS権限・ネットワーク設定によって接続可否が異なります。実カメラの全機種での動作を保証するものではありません。

## 操作

1. 起動画面の「ライブキャプチャ」、または「ファイル > ライブキャプチャ…」を開く。
2. USB/HDMI/iPhoneでは「カメラ・音声を確認」で権限を許可し、カメラと音声入力を選ぶ。マイクを許可できない場合も映像だけの取り込みは利用できる。「音声なし」または「既定の音声入力」、名前付きの音声機器を選択する。IP映像では直接配信URLを入力する。必要な数だけ入力を追加し、アングル名を付ける。
3. パッケージ名・画質を指定し、「録画を開始」で新規保存先を選ぶ。既存パッケージは上書きしない。取り消すとカメラを解放する。
   一部の入力が接続に失敗しても、録画できた入力でコーディング画面を開く。失敗した入力はキャプチャ画面から再接続できる。
4. 全入力から最初の保存区間が届くと通常の映像ウィンドウとタイムラインが開く。コードウィンドウを開き、既存ボタンまたは設定済みホットキーで記録する。
5. タイムラインで過去へシークしてレビュー・コーディングできる。録画は継続する。「ライブ位置」で録画中の各入力が保存できた最新位置へ戻る。標準ホットキーは **Shift + Option/Alt + L**。通常のホットキー設定で変更でき、アングル切替キーも通常再生と共通。
6. 記録中のコードを終了し、キャプチャ画面の「停止して保存」で録画を確定する。保存後は通常のパッケージとして再生・アングル同期・Playlistへの追加・映像書き出しを行う。

キャプチャ設定は独立したサイズ可変ウィンドウで開きます。入力が増えても設定領域だけがスクロールし、開始・停止ボタンは下端に残ります。最小化中も録画処理を継続し、録画中はOSの自動スリープによるアプリ休止を抑制します。明示的なスリープや蓋を閉じる操作を防ぐものではありません。USBプレビューは消音です。IP映像のプレビューには録画と共通の保存済み映像を使います。

## 時刻と同期

コードの開始・終了時刻は、映像ウィンドウで表示している **パッケージ共通時刻** に紐づきます。USBのプレビューや実際の競技場を見た瞬間の壁時計へは記録しません。過去映像を見ながら記録すると、その過去の映像位置にコードが付きます。

録画は約2秒の完了区間として公開します。ライブ位置への移動では録画中の各入力に共通する保存済み末尾から4秒の余裕を取り、入力・エンコード・保存の遅延も加わります。ゼロ遅延のプレビューではありません。ライブ再生が保存済み末尾に追いついた場合は映像を保持して待機し、追加保存後に続きから再開します。手動で一時停止した場合は「ライブ位置」で再開できます。過去のレビュー中に新しい区間が届いてもシーク位置を変更しません。

入力開始を同じセッションの起点に配置しますが、異なる機器の遅延、配信側バッファ、露光タイミングの差を自動計測・補正する機能やgenlockはありません。厳密なアングル間同期は録画終了後に通常のアングル同期で調整してください。録画中の同期配置変更は、追記との競合を防ぐため無効です。

切断後に「再接続」すると、その時点から新しい区間を配置します。切断していた時間は詰めず、映像のないアングルは黒い空白区間になります。初期入力の一部が失敗して全入力が揃わない場合、接続先を確認して再接続するか停止してください。停止後は保存できた入力だけでパッケージを開きます。

## 保存・停止・エラー

- 保存完了したMP4区間と配置を `.metadata/config.json` に順次記録する。`timeline.json` は既存のコーディング保存処理が所有し、キャプチャ処理は上書きしない。
- 入力切断は入力カードに表示する。他の入力の録画は継続する。「再接続」で復帰し、保存済み区間を再録画しない。
- 保存先の空き容量を開始時・録画中に検査する。残量256MiB未満や書込失敗で停止する。外付けドライブは録画終了まで取り外さない。
- デバイス録画の未保存バッファは8MiBまで、1回のIPC転送は最大1MiB。保存が追いつかない場合は当該入力を停止し、画質・入力数の見直しを案内する。
- 「停止して保存」はデバイスの最後のデータを渡してからFFmpegを終了し、完了した区間を保存する。キャプチャ画面を閉じる際は停止・継続を選べる。アプリ終了・キャプチャ画面の異常終了も停止処理を行う。
- 強制終了や電源断では保存済みの区間とコードを維持するが、処理中の区間・未保存コードは失われる場合がある。既存パッケージを開いて確認し、新たな録画は新規パッケージへ保存する。中断セッションを同じファイルへ再開する機能はない。

## プライバシーと境界

配信URL・認証情報・OSのデバイスIDはキャプチャ画面とプロセスのメモリ内で扱い、パッケージ、履歴、IPC状態通知、公開ログへ保存しません。FFmpegの標準エラーには接続情報が含まれ得るため、そのままログや画面へ転送しません。実行中のOSプロセス情報には接続先が現れ得るため、プロセス一覧やデバッグダンプを公開しないでください。

カメラ・マイクの許可は専用ウィンドウの専用セッションで、明示操作後にだけ有効になります。録画変更IPCはそのウィンドウのメインフレームのみ受理し、通常のパッケージウィンドウは自分の録画状態のみ読めます。IP配信の入れ子URLからローカルファイル・pipeを読めないようFFmpegのプロトコルを制限します。

## 実装と検証の入口

- 描画: `src/features/liveCapture/*View.tsx`（propsのみ、Storybook対応）
- デバイス接続・転送: `useCaptureController.ts` / `deviceRecorder.ts`
- セッション・保存・FFmpeg: `electron/src/liveCapture/`
- 通常再生への追記: `useLiveCapturePlayback.ts`、既存Timeline IPC
- 書き出し: 音声パディングでMP4の長さが延びても、保存された区間長を超えて隣の区間に重ねない。映像情報の取得は書き出し範囲と出力サイズの基準映像に限定し、同時実行は4件までに制限する。
- 正本型: `src/types/liveCapture.ts`、`src/types/ipc/liveCapture.ts`、`src/renderer.d.ts`
- 回帰: `scripts/e2e-live-capture.mjs`。Chromiumの模擬カメラとlocalhost上の合成HTTP映像のみ使い、実カメラや私的な映像を使用しない。
- ネットワーク検証: 同梱macOS FFmpegとlocalhostのMediaMTX 1.21.1に合成映像・音声を配信し、RTSP/TCP・RTMP・HLSそれぞれからH.264/AAC区間を保存してffprobeで確認した。RTSPにはdemuxer固有の `timeout`、HTTP/RTMPには `rw_timeout` を使う。TLS・認証方式・実機固有の互換性は、このテストの確認範囲に含まない。
- 設計判断: [ADR 0053](adr/0053-live-capture-package-timeline.md)
