# 0048 Playlist instance notes

## Status

Accepted

## Date

2026-09-21

## Context

PlaylistにコピーされたTimelineの`memo`と、Playlist内で編集する`note`が別々に表示され、映像出力には前者だけが渡されていた。発表用の文章を編集しても出力映像と一致せず、どちらを編集するべきか分かりにくかった。

## Decision

- Playlist文書v4の自由記述は`note`へ統一する。Timelineから追加するときにノートをコピーし、その後はPlaylist内の編集として保存する。元Timelineへ暗黙に書き戻さない。
- 旧文書の`memo`はロード時に移行する。両フィールドの文章が異なる場合は`note`、空行、`memo`の順で両方を保持する。同文は重複させない。最新の型・保存文書には`memo`を残さない。
- InspectorとSorterの入力、検索、保存、Undo、書き出しは同じ`note`を使う。共通の映像書き出し要求では既存の`memo`フィールドへ境界で変換し、Timelineの保存形式とIPCの変更を不要にする。
- オーバーレイテキストを含めるかは、各書き出しダイアログを開くたびに未選択とする。含める／含めないを明示するまで書き出さず、一般設定の旧値は正規化で除去する。Paintとフリーズはこのテキスト選択から独立する。

## Consequences

- 既存の文章を失わず、編集したノートを映像へ出力できる。旧アプリでv4を開くと編集ノートの映像出力が正しく扱われないため、対応版で使用する。
- Playlistは発表用に独立したノートを持つ。コピー後のTimelineとPlaylistの双方向同期は行わない。
- 長文は折り返し・複数行で描画し、映像内に収まるよう文字を縮小する。長すぎるノートは読みにくくなるため、短いコーチングポイントを推奨する。
- 操作・参照資料・検証の正本は[Playlist仕様](../playlist-features.md#ノートの編集と映像出力)とする。
