## Context

コードウィンドウの作成・ファイル選択・ウィンドウ表示が「コーディング」と「ウィンドウ」の両方へ混在し、同じ「コードウィンドウを開く」が複数箇所に存在していた。この項目は対象ファイルを示さないまま空の独立ウィンドウを表示するため、どのコードウィンドウを操作するのか判断できない。

Sportscodeはコードウィンドウを保存可能なドキュメントとして扱い、作成を `File > New > Code Window`、既存ファイルの利用をファイル選択または最近使った項目から開始する。macOSのメニューバーも、ドキュメントのライフサイクル、現在の機能モード、既存ウィンドウの管理を別のメニューへ分けることが期待される。

## Decision

- 映像パッケージとコードウィンドウの「新規」「開く」は、すべて「ファイル」メニューへ集約する。
- 「ファイル > 新規 > コードウィンドウ…」は保存先を選択して空の `.stcw` を作成した後、そのドキュメントを独立ウィンドウで表示する。
- 「ファイル > 開く > コードウィンドウ…」は `.stcw` 選択ダイアログを必ず表示し、選択されたドキュメントを独立ウィンドウへ反映する。
- 「コードウィンドウを開く」のように対象ドキュメントが不明なコマンドは設けない。
- 「コーディング」メニューはラベルモードなど現在のコーディング動作だけを扱い、ファイル作成・選択を置かない。
- 「ウィンドウ」メニューは分析・プレイリストなどウィンドウの表示とmacOS標準のウィンドウ管理だけを扱い、ドキュメント作成を置かない。
- ファイル選択、保存先選択、ウィザードなど追加操作を必要とするメニュー項目には末尾へ `…` を付ける。
- `Command+N` は映像パッケージ作成ウィザード、`Command+Shift+N` はコードウィンドウ作成、`Command+O` は映像パッケージ選択、`Command+Option+O` はコードウィンドウ選択に割り当てる。

## Consequences

- コードウィンドウを開く操作では対象ファイルが作成または明示選択され、表示内容が不明な空ウィンドウは生じない。
- ファイル操作とモード操作の重複がなくなり、Sportscodeから移行したユーザーが標準の「ファイル > 新規 / 開く」から目的のドキュメントを探せる。
- `menu-create-video-package` はpreloadのtyped listenerを通して常駐する動画プレイヤーcontrollerへ渡し、映像表示中でもホームへ戻って作成ウィザードを開く。
- 最近使った項目は現時点では映像パッケージだけを保持するため、「最近開いた映像パッケージ」と明示する。コードウィンドウの履歴を追加する場合は、ファイル種別を判別して正しいloaderへ振り分ける必要がある。
