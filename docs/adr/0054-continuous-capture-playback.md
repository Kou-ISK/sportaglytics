# 0054 Continuous capture playback

## Status

Accepted

## Date

2026-09-23

## Context

[ADR 0053](0053-live-capture-package-timeline.md)の録画パッケージは、保存確定した短いMP4区間を通常のクリップ再生経路へ渡していた。区間ごとのプレイヤー生成・デコーダー初期化でライブ視聴が途切れ、操作画面が映像を覆うと背景の描画時計も抑制され得た。保存の完了単位と再生ソースの寿命を分ける必要がある。

現行Hudl Sportscodeの公開仕様はキャプチャ中の滑らかなシーク、プレビュー/録画ソースの共用を示すが、内部のファイル配置・区間長は断定できない。旧製品の区間長を模倣することを設計根拠にしない。

## Decision

- ADR 0053の確定区間・通常パッケージ・入力権限・共通時計の契約を維持する。
- USBのMediaRecorderはH.264対応時に直接エンコードし、FFmpegは映像copyと音声変換・分割保存を担う。H.264非対応時はVP8入力を変換する。入力の上限解像度と30fpsをgetUserMediaで制約し、キーフレーム間隔は2秒を要求する。
- 新規録画を単独再生も可能なfragmented MP4へ保存する。アングルの`playbackFormat`で明示し、ロード時に認識する。通常のMP4は従来経路を使い、既存パッケージを自動変換しない。
- アングルにつき一つのMediaSourceへ、保存区間の配置時刻をtimestampOffsetとして追記する。再生位置の先10秒、後ろ20秒を目安にバッファを制限する。過去レビューでは必要区間を再読み込みし、再接続時の空白は維持する。
- キャプチャRendererは録画の所有者として非表示でも存続する。パッケージの操作文脈に関連付けるが、パッケージ画面を閉じる際の補助Window一括終了対象に含めない。録画の停止は明示的に行い、アプリ終了・録画Rendererの異常終了時の確定処理は従来どおり実施する。
- 録画パッケージのMain Rendererは録画中だけbackground throttlingを無効にする。Code Windowからのコマンド購読は一度だけ登録し、最新のハンドラと表示時刻を参照する。

## Consequences

保存区間の多さによってプレイヤー数やバッファが増えなくなる。録画完了後・再オープン時も同じ形式情報で連続再生する。SourceBufferのcodec対応・タイムスタンプ整合性はElectron実行環境での回帰対象となる。失敗時は警告を出して単独区間再生へ戻し、録画自体は止めない。パッケージのファイル数、入力エンコード負荷、機器固有の遅延をゼロにする設計ではない。
