# 0047 Playlist Sorter presentation order

## Status

Accepted

## Date

2026-09-21

## Related ADRs

- Supersedes: [0025](0025-playlist-document-presentation-order.md)
- Superseded by: N/A

## Context

Sorterで並べたクリップをその順序で再生・書き出す要求がある。v2の行順→行内順序だけでは、所属行を維持したまま行をまたぐソート結果を保存できない。表示だけのソートでは確認した順序と発表する順序が異なる。

## Decision

- 文書v3はクリップの`presentationOrder`を全体の再生順とする。`rowId` / `rowOrder`と`rows`はOrganizerの構造として維持する。
- Sorterの並べ替えは全クリップを対象とする単発の文書編集とし、再生・保存・書き出しは同じ共有関数で順序を解決する。順序変更を1回のUndoで戻せるようにする。
- ソートは行内の順序も更新するが所属行と注釈を変えない。現在のクリップは配列番号ではなくIDで保持する。Undo/Redoは復元する配列を同期的に返す。
- v1のflat順序、v2の行順→行内順序からロード時に全体順序を生成する。正規化は冪等で、未採番の追加クリップは末尾に置く。保存はv3へ統一する。
- Organizerの行移動・所属変更は行順への明示的な再編成、行内の並べ替えは該当行が占める再生位置内での置換とする。
- 検索、列表示、モード、Inspector等は従来どおりウィンドウ状態とする。検索中のソートも文書全体を対象とし、範囲選択は表示結果を使う。

## Consequences

- Sorterで確認した再生番号がファイルの再読込後や映像出力でも一致する。行構造とPaintを失わずにプレゼンテーションを構成できる。
- v3非対応の旧アプリは行をまたぐ全体順序を復元できない。旧文書の読込互換と、旧アプリでのv3編集互換は区別する。
- 自動ソートは行わず、クリップの追加・内容変更後は必要に応じて再度ソートする。Undoは順序変更を戻し、検索や列表示の状態は変更しない。
- 単体テストで移行と順序の不変条件を、実ElectronとFFmpegで再生・保存・出力までを検証する。
