# 0065 Unified project open

## Status

Accepted

Separate-destination migration superseded by [0067](0067-in-place-package-updates.md).

Supersedes [0006](0006-application-document-formats-and-file-associations.md). 文書形式・OS関連付け・原本保持の契約は引き継ぎ、プロジェクトの新旧を選ばせる入口だけを統合する。

## Date

2026-10-17

## Context

利用者は作成時の保存形式を判断する必要がない。原本を再度開いた際、別保存先や連番の欠番によって新しいコピーが作られると、編集済みの移行先を見失いやすい。

## Decision

- パッケージとプロジェクトフォルダは同じ「パッケージを開く」・OS open・履歴・dropから内容を検証する。XML取り込み、映像追加、保存先選択は目的の違う操作として維持する。
- 既知の旧構造だけを原本と別のstagingへコピーし、ファイル一覧・サイズ・小さいメタデータの内容、変換済み構造・参照、原本不変を検証して完成renameする。作業中の予約名は通常openで拒否する。
- 完成先の探索は新しい名前の割当より先に行う。端末内索引は原本realpathと文書revisionをキーに別保存先を記憶する。候補のmarkerと構造を再検証し、編集済みコピーを保持する。
- コピー中変更検出には厳格なfingerprint、再利用にはFinderメタデータやdirectory mtimeの影響を除いたrevisionを使う。旧markerのfingerprintも認識する。
- 登録先が未接続なら再接続・移動先選択へ案内し、自動再コピーしない。破損した完成先は上書きしない。索引が壊れた場合も推測による再コピーを行わず、完成パッケージを直接開ける。
- 完成rename後の索引保存失敗は警告として返し、完成した文書を利用可能にする。次回は完成先を直接開くよう案内する。
- 原本のOS open予約、移行先をbindした予約をそれぞれ失敗時に解放する。busyは成功・取消・失敗の全てで解除する。

## Consequences

形式の判断を利用者へ求めず、再実行で同じ編集済み文書を開ける。原本へのリンク追記はしないため、索引の損失と別保存先の移動が同時に起きた場合は完成先の明示選択が必要になる。全動画のバイトhash・毎回の全尺decode、電源断や別アプリによる同時変更の完全保護は提供しない。メディア構造の検証とプレイヤーのdecode成功は別に扱う。
