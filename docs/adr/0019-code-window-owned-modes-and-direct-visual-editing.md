# 0019 Code-window-owned modes and direct visual editing

## Status

Accepted

## Date

2026-08-02

## Related ADRs

- Supersedes: [0018 Document-oriented menu structure](0018-document-oriented-menu-structure.md)
- Superseded by: N/A

## Context

ADR 0018でドキュメント操作を「ファイル」へ集約した後も、アプリ全体のメニューバーには「コーディング」が残り、独立コードウィンドウのラベルモードを外部から切り替えていた。しかしコード／ラベル／編集は開いている `.stcw` の作業状態であり、複数のコードウィンドウが存在し得る環境では、アプリ全体のメニューから操作対象を一意に判断できない。

また、編集時のボタンは塗りつぶされたカードとして描画され、実行時の透明背景・色付き輪郭とは外観、文字サイズ、配置が異なっていた。編集結果を実行表示として予測するためにモードを往復する必要があり、直接操作の利点を損なっていた。ウィンドウサイズへ編集キャンバスを自動追従させる処理は、編集モードへ入るだけで保存対象の寸法を変える副作用も持っていた。

## Decision

- 「コーディング」トップレベルメニューを廃止し、コード／ラベル／編集の切替は対象の独立コードウィンドウ内だけに置く。
- 映像パッケージとコードウィンドウの新規作成・選択は「ファイル」、既存補助ウィンドウの表示は「ウィンドウ」へ置くというADR 0018のドキュメント指向分類を継承する。
- コードウィンドウの実行表示と編集表示は、propsだけで描画できる共通のボタンsurfaceを使用する。編集状態は選択輪郭、ドラッグcursor、削除・resize handleだけを重ね、保存される色、輪郭、文字、位置、寸法は実行表示と一致させる。
- 編集モードへの切替やBrowserWindowのresizeでは、`.stcw` の `canvasWidth` / `canvasHeight` を自動変更しない。キャンバスが表示領域を超える場合は編集領域をscroll可能にする。
- アプリ全体の設定とヘルプは独立した補助ウィンドウとして維持し、設定は少数の明確なカテゴリ、ヘルプは検索可能なトピック一覧とsystem appearanceへ適応する読書領域で構成する。

## Consequences

- どのコードウィンドウのモードが変わるかが明確になり、メニューバーの対象不明な状態操作がなくなる。
- 編集中のボタンが実行時と同じ外観になるため、別モードでの確認回数が減る。共通surfaceの変更は実行・編集の両方へ反映される。
- BrowserWindowを狭くしても保存キャンバスは変化せず、scrollして編集する。キャンバス寸法の変更は明示的な編集操作として別途提供する必要がある。
- 旧preloadのラベルモードmenu listenerは公開面から削除される。コードウィンドウ内の切替は型付きcommand IPCを通してmain runtimeへ同期する。
