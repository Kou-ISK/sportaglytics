# 0046 Coalesced playback corrections

## Status

Accepted

## Date

2026-09-21

## Context

複数クリップの再生は共通時計を正本とする（ADR 0040）。元動画の時計へ毎描画フレームでシークを発行すると、高速再生ではデコードが終わる前に次のシークが入り、待機が長引く。画面側と操作側の両方から書く場合、元動画の切替前のプレイヤーへ新しいクリップの時刻を渡す競合も生じる。

## Decision

- クリップを持つ自動同期再生は`useMediaTimeSync`を元動画の時刻適用元に統一する。コントローラーは共通時計を更新し、元動画の解決後に適用する。
- デコード中は既存シークを中断せず、最新の要求だけを保持する。停止中は完了通知でも未適用の最新時刻へ合わせる。要求位置が先頭PTSより前にあるとデコーダーが実フレームへ補正するため、未到達の同じ要求をseeked / canplayから繰り返さない。要求時刻の変更、元動画の読み直し、明示シーク、loadeddataによる初期シークの復元は再適用できる。要求位置へ到達した時点で未解決要求の記録を解除し、ソースの読み込み復元で後から0秒へ戻されても同じ目標へ再補正する。未到達のクランプ要求は引き続き繰り返さない。
- 再生中はネイティブの連続再生を使う。ずれの補正は最低250msの間隔と再生速度に応じた許容差を設け、明示的シークと停止時の位置合わせはこの待機間隔から除外する。
- 共通時計は、現在位置のネイティブ動画がシーク中または後続フレーム待ちの場合に進行を保留する。再生意図と一時的な待機を分離し、全アングルのネイティブ再生も一緒に保留する。時計だけを止めると他のアングルが先へ進み、復帰時の補正が新しいデコード待ちを起こす。停止操作が入った場合は、準備完了によって再生を再開しない。待機時間を復帰後に加算すると、その間のずれで再シークとデコード待ちが連鎖するため、待機した経過時間は破棄する。実クリップのない空白と終了済みフレームは進行を継続し、次のクリップへ到達できるようにする。
- canplay待機と非同期playの再試行は、その再生要求の寿命内に限定する。停止・unmount後の通知から再生しない。
- 単一の元動画だけで共通クリップ時計を持たない経路と手動同期は、既存の直接シークを維持する。

## Consequences

共通時計・保存形式は維持する。高速再生中の細かいずれよりデコードの連続性を優先するが、明示的な停止・シークは最新の要求位置へ収束させる。コーデックやストレージ自体の待ち時間は解消できず、機種をまたぐ一律の速度保証はしない。合成映像で元動画境界・空白・再生状態・シーク回数を検証し、遅延通知の競合はHook試験で検証する。

アングル同期プレビューでもデコード中のseekを中断せず、未到達の同じ停止要求を繰り返さない。新しい時刻・元動画・再生から停止への変更は適用し、到達済みの位置が読み込みで戻された場合は再補正する。非ゼロ先頭PTSと遅延通知はHook試験と3/4アングルE2Eで確認する。
