# Playlistの操作と保存契約

Playlistは、タイムラインで選んだ映像区間を整理し、連続再生・提示・書き出しを行う専用ウィンドウです。描画・位置キー・追尾の操作と制約は[Paint](tactics.md)を正本とします。本書はウィンドウ、再生順、保存、書き出しの契約を扱います。

パッケージを参照するPlaylistは、各アイテムの共通時刻からその時点の元クリップを選びます。前半・後半が別ファイルでもアングルごとに切り替え、アングル全体の同期補正も適用します。元ファイルを直接シークする時刻を注釈・アイテムの保存時刻へ流用しません。同期情報はアイテム切替・再フォーカス時に読み直します。読込失敗時は接続を確認して「再試行」を押します。操作の正本は[マルチアングル同期](user-guide.md#マルチアングル同期)です。

## 書き出し前の確認

Playlistの映像出力はTimelineと共通の事前確認を使います。各クリップで選択したアングルと元パッケージの必要な映像を確認し、欠落があればエンコード開始前に通知します。保存先の既存ファイルと同名なら連番で保存します。チェック範囲と制約は[映像クリップ書き出し](user-guide.md#タイムラインのクリップ書き出し)を正本とします。サーバーや追加サービスの契約は不要です。

## 作業の流れ

1. タイムラインでインスタンスを選択し、右クリックメニューまたは既定の `Cmd/Ctrl+Shift+P` からPlaylistへ追加します。
2. PlaylistウィンドウでOrganizerまたはSorterを選び、クリップを整理・確認します。
3. クリップを選択して再生し、必要に応じてノート、フリーズフレーム、Paintの描画を追加します。
4. `.stpl` として保存するか、映像クリップを書き出します。

Organizerは行と行内のクリップ順を編集する面です。Sorterは表で比較・検索し、クリップの再生順を並べ替える面です。列見出しまたは「並べ替え」の項目と昇順・降順で、全クリップの再生・書き出し・保存順を変更します。検索中もソートは全クリップを対象とし、検索だけでは順序を変更しません。ソートは1回のUndoで戻せます。現在のクリップと選択はIDで維持し、再生中のソートでは一時停止します。Shift選択は検索結果の見えている行の範囲に限定します。

## 再生と表示

- Playlistの再生バーは、メイン映像と同じ角丸・半透明の共有コントローラーを使います。時間表示、シーク、再生速度、前後移動をまとめて操作できます。
- シーク領域に描画のある位置を表示し、目印から該当時刻へ移動できます。Paint内では、図形ごとの表示区間と位置キーを下部タイムラインから直接編集します。
- アングル1、アングル2、2画面の表示に対応し、描画対象のアングルを分けて扱います。
- Playlistウィンドウの縦横比は自由です。メイン映像ウィンドウの固定縦横比を適用しません。映像とOrganizer/Sorter、Inspectorの作業領域に合わせてサイズを調整できます。
- フリーズフレームは指定時刻での静止表示と描画を保持します。再生中の図形表示・追尾とは別の編集単位です。
- Paint中の `Delete` / `Backspace` は位置キーまたは図形へ作用し、クリップは削除しません。文字・数値入力やダイアログでは通常の入力操作を優先します。

## `.stpl` の保存契約

`.stpl` は `playlist.json` を含むディレクトリ型パッケージです。埋め込み保存では `videos/` 以下に切り出した映像を含め、参照保存では元映像へのパスを保持します。

| 形式        | 内容                 | 持ち運びの条件                                                 |
| ----------- | -------------------- | -------------------------------------------------------------- |
| `embedded`  | 対象区間の映像を内包 | パッケージ内の映像も含めて移動する                             |
| `reference` | 元映像への参照を保持 | 元パッケージの識別情報と相対位置で再接続。下記の移動条件を参照 |

埋め込み映像はクリップ先頭を0秒とします。時刻の変換と描画のロード時移行は保存・読込層で行い、View側に旧形式の分岐を持ち込みません。JSONを直接編集する運用は保証せず、アプリの保存・正規化を通してください。

### 参照先の移動と再接続

- 元の `.stpkg` へ識別IDを保存し、PlaylistにはID、パッケージ内の映像位置、Playlistからの相対位置を保持します。名前だけが同じ別の試合へ自動で接続しません。
- `.stpl` と `.stpkg` を含むフォルダをまとめてコピー・移動した場合は、その相対位置を優先します。元のフォルダが残っていても、コピー先の映像を利用します。同じフォルダに置いたパッケージの改名もIDで確認します。
- Macではローカルに保存したOS bookmarkで移動・改名を追跡します。アプリの再起動後も利用します。bookmarkは端末内のアプリデータにだけ保存し、Playlistへ含めません。ボリューム・ファイルシステムによって追跡できない移動があります。
- Windowsを含め、移動先の `.stpkg` を一度開くとIDに対する現在地を更新します。自動復元できない場合はクリップ詳細の「元パッケージを再接続…」から選び直します。同じ元パッケージを参照する全クリップ・両アングルをまとめて更新し、ノート・Paint・既定アングル・順番を維持します。
- 外付けドライブの切断・元映像の削除時は接続エラーを表示し、元の参照情報を消しません。接続して「再試行」で復元できます。切断中に保存しても参照を保持します。
- 旧Playlistは元映像が存在する状態で一度開いて保存すると識別情報を持ちます。既に移動済みでIDがない旧データは最初の一度だけ移動先を指定してください。パッケージ外の単独映像やIDを書けない読み取り専用パッケージには、同じ移動追跡を保証しません。

設計は[ADR 0051](adr/0051-portable-playlist-references.md)を参照してください。

### クリップごとの既定アングル

1. OrganizerまたはSorterでクリップを選びます。
2. 右側の「クリップ詳細」→「既定の映像」でアングル1またはアングル2を選びます。
3. 次のクリップも同様に設定します。連続再生ではクリップに入るたびにその既定アングルへ切り替わります。設定は保存・Undo/Redoの対象です。Sorterの「映像」列にも既定アングルとその参照映像名を表示します。
4. 映像書き出しで「各クリップの既定アングル」と「1ファイル」を選ぶと、例えばアングル1→アングル2→アングル1を1本の映像へ出力します。ノートと選択アングルのPaintも適用します。プレビューと事前検査も同じアングルを使います。

従来の単一アングル指定・全アングル・2画面合成も選べます。ショートカットや表示メニューによる一時的なアングル切替は、クリップの既定値を書き換えません。旧クリップの既定値はアングル1です。Playlistの既存の2アングル構成を対象とし、メイン映像の3・4アングル表示とは別です。[ADR 0052](adr/0052-playlist-default-angles.md)。

### Hudl Sportscodeの参照仕様

2026-09-22に[現行の公式リリースノート](https://www.hudl.com/releases/sportscode)を確認しました。元映像を同じフォルダや同一Mac内の別の場所へ移した参照Playlistの継続利用、クリップごとの映像・音声アングル、既定アングルの保存が説明されています。[公式の書き出し説明](https://www.hudl.com/blog/hudl-sportscode-update-august-2020)では、全アングル・表示中・既定アングルと、単一ファイル・クリップ別・行別の組合せを示しています。本実装はこの文書契約を参考にしており、Sportscode内部のファイル追跡実装や最新実機の完全一致を確認したものではありません。

### 文書の正規順序

現行の `schemaVersion` は **5** です。v5は参照先の識別情報とクリップごとの既定アングルを保存し、v4のノートと再生順を維持します。

- `rows` がOrganizerの行を表し、各クリップは `rowId` と `rowOrder` を持ちます。
- 正規順序はクリップの `presentationOrder` です。再生・保存・書き出しは `getPresentationItems` を共通利用します。Sorterのソートは所属行を変えず、行をまたいだ再生順と行内の順序を更新します。Organizerでも再生番号はこの順序です。
- Organizerの行の移動・所属行の変更は、明示的に行順へ再編成します。行内の並べ替えは他行の再生位置を維持します。新規クリップは再生順の末尾へ追加します。
- v2は従来の行 `order` → `rowOrder` から再生順を移行します。v3非対応の旧アプリでは行をまたぐ再生順を復元できないため、v3を保存したファイルは対応版で利用してください。
- 行情報のない旧flat形式は既定行「クリップ」へ移行し、元の配列順を保持します。`actionName` による暗黙の再グループ化は行いません。
- 正規化は冪等であり、繰り返し読み込み・保存しても行やクリップを増殖させません。

ソートによる順序変更は文書編集として保存・Undoの対象です。検索、列の表示状態、Organizer/Sorterの切替、Inspector幅はウィンドウの表示状態であり、それだけでは未保存変更にしません。並べ替え後にクリップを追加・編集しても自動的な再ソートは行いません。判断背景は[ADR 0047](adr/0047-playlist-sorter-presentation-order.md)を参照してください。

描画の座標、位置キー、素材の保存範囲は[Paintのデータ契約](tactics.md)に従います。型定義を本書へ複製せず、`src/types/playlist/core.ts` を参照します。

## 複数ウィンドウと保存確認

保存済みファイルは「ファイル > 開く > プレイリスト…」から選択します。起動画面・映像・PlaylistのどのWindowからでも使用でき、文書を検証してから独立Windowへ渡します。キャンセル・読込失敗時は新しいWindowを作成せず、編集中の文書を保持します。既存の「ウィンドウ > プレイリストを開く」は空のPlaylistを表示する操作です。

複数のPlaylistを独立したウィンドウで開けます。同じファイルへの要求は既存ウィンドウをフォーカスします。文書を変更して閉じるときは保存確認を行います。

メインとの同期・コマンド転送はPackage Sessionの所有権に従います。別パッケージの映像・時刻・選択が混線しないよう、Mainが所有するSessionを境界にします。Rendererが任意の他ウィンドウを直接操作する構成にはしません。

## ノートの編集と映像出力

- Timelineのインスタンスに付けた自由記述は「ノート」と呼びます。Playlistへ追加するとコピーされます。Playlist側で編集しても元Timelineのノートは変わりません。
- Sorterの「ノート」セルをダブルクリック、またはセルへフォーカスしてEnter/F2で直接編集します。Enterまたは外側のクリックで確定、Shift+Enter / Control+Enterで改行、Escで取消します。Control+Tabで確定して次の表示行、Shift+Control+Tabで前の表示行へ移ります。
- Inspectorのノート欄でも直接入力できます。Enterで改行、外側のクリックで確定します。広い入力欄が必要な場合は「ノートを編集」を開きます。
- 入力中のDelete/Backspace、スペース、矢印、Undoは文字編集を優先します。確定後のノート変更はPlaylistのUndo/Redo、保存・再読込の対象です。空欄にすれば出力からも消えます。
- v3以前の`memo`と`note`は読込時に一つの`note`へ移行します。異なる文章は編集済みノート→空行→旧メモの順に保持し、同文は重複させません。保存時は旧フィールドを除去します。
- 書き出しで「含める」と「ノート」を選ぶと、編集済みの文章が映像へ焼き込まれます。明示した改行・空行と長文の折り返しを保持します。タイトル・ラベルを含む全体を映像高の20%以内に制限し、背景は必要な高さだけ下端へ表示します。文字は1080p換算で30px、最小24px、行送り1.25倍、上下余白は各1%です。出力解像度に比例するため、ウィンドウの大きさでは変わりません。「含めない」でもPaintとフリーズは出力されます。
- 「含める」では実映像へ文字を重ねたプレビューを表示します。「確認するクリップ」で対象を切り替えられます。クリップ先頭のテキスト配置を確認する静止画で、Paint・フリーズの効果は含みません。
- 読み込み中・プレビューエラー・高さ超過中は書き出しを開始できません。高さ超過は全対象クリップをチェックし、該当名を一覧表示します。ノート編集のためにキャンセルするか、出力項目のチェックを外してください。原文を勝手に省略せず、最小文字サイズより小さくしません。
- 全アングルを選択した場合は各出力を検査し、マルチアングルでは合成後の映像全体に一つの帯を描きます。Mainも保存先選択前に上限を検証します。[設計判断と参照根拠](adr/0049-bounded-export-text.md)。

### Hudl Sportscodeとの対応

2026-09-21に確認した[公式機能一覧](https://www.hudl.com/products/sportscode/tiers)はTimelineでのNotes編集とOverlay Textを説明しています。[公式Playlistワークフロー](https://www.hudl.com/blog/opposition-analysis-using-hudl-sportscode-in-basketball)はPlaylist内のノート編集と、ノート・描画を含む動画出力を説明しています。[公式更新履歴](https://www.hudl.com/releases/sportscode)の12.2.47にはControl+Tabによるノートの確定・次行移動、12.3.4にはControl+Enterによる改行の記載があります。これらを操作の根拠とし、同じクリップの「メモ／ノート」という独自の二重入力を廃止します。Sportscodeの行ノートは対象が異なる情報であり、この統合とは別です。最新実機での細かなキー挙動・文字配置の完全一致までは検証していません。毎回の書き出し確認はユーザー要求による仕様です。

判断背景は[ADR 0048](adr/0048-playlist-instance-notes.md)を参照してください。

## 映像の書き出し

プレイリストを選んだ状態で「ファイル > エクスポート > 映像クリップ（オーバーレイ付き）」を実行すると、このプレイリストの書き出し設定を開きます。ツールバーと書き出しショートカットも同じ設定を使用します。

書き出しダイアログで次を指定します。

| 項目     | 選択肢                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------ |
| 対象     | 全クリップ / 選択中のみ                                                                          |
| まとめ方 | 1本に連結 / インスタンスごと / アクションごと                                                    |
| アングル | 各クリップの既定アングル / 全アングルを個別出力 / 単一アングル / 2アングルを合成                 |
| 情報表示 | 毎回、テキストを含める／含めないを選択。含める場合はアクション名・番号・ラベル・ノートを個別選択 |

一般設定や前回の選択は引き継ぎません。「含める／含めない」が未選択の間は書き出しを開始できません。メニュー、ツールバー、ショートカットは同じ確認を通ります。含める場合は対象クリップのノート本文も確認できます。キャンセル後の再実行でも選択が必要です。

フリーズフレームとPaintの描画も書き出しデータに含めます。単一／全アングルの出力では各クリップ自身の指定アングルとそのPaintを使用します。指定アングルのないクリップが含まれる場合は、別クリップの映像を代用せずエラーを表示します。2画面合成では、第2映像の縦横比を保って第1映像の高さへ揃え、各映像のPaintも同じ比率で拡大縮小します。動きのサンプル数や書き出し上限は[Paintの制約](tactics.md)に従います。

情報表示をオフにした場合の高速コピー条件、再エンコードが必要な条件、準備範囲は[共通の高速書き出し仕様](user-guide.md#元の画質を保つ高速書き出し)に従います。Paintと静止挿入は情報表示の設定にかかわらず出力します。

進行状況は同期区間の準備から専用の進捗ウィンドウに表示します。失敗した場合は元映像、保存先の権限、空き容量を確認し、必要ならエラー詳細を開きます。FFmpeg実行・一時ファイル・キャンセルはMain側の責務であり、RendererのViewから直接扱いません。

## 外部から開くときの準備完了

プレイリストの新規ウィンドウはpreloadで外部オープン通知を購読してから専用ready IPCを送信し、mainが保持する文書パスを受け取ります。画面の初期化より先に通知を送って文書が空になる競合を避けます。この境界はMac/Windows共通です。

PaintのUndo直後に保存する場合も、履歴中のクリップに保存された描画を優先します。一時的な描画キャッシュの更新待ちによって、復元した図形を古い状態で保存しません。
